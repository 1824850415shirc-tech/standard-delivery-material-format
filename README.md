# Standard Delivery Material Format

写一份交付文档，正文往往只是工作的一半。封面、目录、标题、正文、表格、页边距和字体，都可能需要反复调整。

这个 Skill 想做的事情很简单：在遵守格式规范的前提下，帮助你把已有材料整理成一份可以继续编辑和交付的 DOCX 文档，尽量少花时间手动刷格式。

## 1. 目的

这个 Skill 适合用来编写有固定格式要求的交付文档。

它把内容整理和文档排版放在同一套流程里：先读取技术资料、代码、合同或现有文档，和你一起确认大纲，再生成正文并套用预设样式，最后输出 DOCX。

它不会替你决定项目事实。材料里没有的信息会保留为待补充项，有冲突的内容会先请你确认。

## 2. 特点

### 2.1 格式处理已经融入 Skill

封面、目录、标题层级、正文、表格和页面设置都使用预设样式。生成正文时，格式会一起处理，不需要再从头逐段调整 Word 样式。

封面单位默认是 `XX科技`。项目名称、文档名称、版本和日期从 Markdown 的封面配置读取，不再写死在 Word 模板中。

### 2.2 样式可以继续维护

文档样式和内容模板分开保存。以后需要调整字号、字体、页边距或表格样式时，可以修改统一模板，不必逐份文档返工。

### 2.4 先确认，再生成

整个过程采用 HITL（Human in the Loop）方式：

1. 先收集和核对已有材料。
2. 根据材料和模板生成带简要说明的大纲。
3. 等你确认大纲。
4. 确认后再生成完整正文和 DOCX。

这样可以尽早发现章节不合适、材料不足或理解偏差，避免整篇写完后再大改。

### 2.5 不用空话填满文档

内容以用户提供的材料为准。没有依据的信息不会被写成事实，而是标记为 `【待补充：具体信息】`。合同约定、技术实现和实际运行情况也会分别核对，不会混在一起下结论。

## 3. 使用指南

### 3.1 安装 Skill

下载项目后，将整个目录放入 Codex 的个人 Skill 目录。确认目录中保留 [SKILL.md](SKILL.md)、`templates/`、`docs/` 和 `scripts/`，然后重新打开 Codex 会话。

如果本地 Python 环境缺少 DOCX 处理库，可在项目目录执行：

```bash
python3 -m pip install -r requirements.txt
```

### 3.2 发起任务

在 Codex 中调用这个 Skill，并说明你要编写的文档。例如：

```text
请使用 $standard-delivery-material-format 帮我写一份详细设计说明书，最终输出 DOCX。
```

### 3.3 提供已有材料

Skill 会先请你提供相关材料。已有多少就提供多少，不需要为了凑齐清单临时编写。

详细设计说明书通常会用到：

- 需求规格说明书或技术规格说明书；
- 源代码、仓库目录或关键模块代码；
- 架构图、部署图和接口文档；
- 数据库设计和配置清单；
- 合同、任务书或验收要求。

其他文档的建议材料见 [材料清单](docs/材料清单.md)。

### 3.4 确认大纲

收到材料后，Skill 会先整理材料范围、信息缺口和文档大纲。每个章节会写明准备写什么，以及依据哪份材料。

此时可以增加、删除或调整章节。只有明确回复“确认大纲”后，Skill 才会开始写正文。

### 3.5 生成并检查 DOCX

正文完成后，Skill 会按照预设样式生成 DOCX。交付前建议用 WPS 或 Word 打开文档，更新目录并检查分页、表格和图片位置。不同办公软件和字体环境可能造成细微差异，这一步仍然值得保留。

完整流程见 [HITL 工作流](docs/HITL工作流.md)。

## 4. 模板维护

新增模板时，可以从对应项目阶段复制一份相近的 Markdown 文件，再修改封面名称、文档标题、章节和每节编写提示。编写提示使用 HTML 注释保存，只帮助起草，不会进入 DOCX。封面信息保存在文件开头的 YAML 配置中，默认编制单位是 `XX科技`。

内置模板默认使用 `XX科技` 作为编制单位，不包含真实人员、客户或项目信息。提交模板前运行：

```bash
python3 scripts/validate_templates.py
python3 -m unittest discover -s tests -p 'test_*.py'
```

具体规则见 [模板编写规范](docs/模板编写规范.md)。

## 5. 使用边界

- 文档质量取决于已有材料和用户确认，Skill 不会自动补出不存在的项目事实。
- DOCX 可以继续编辑，但修改统一样式后，已有文档需要重新生成或单独处理。
- 自动校验可以发现结构问题，不能代替最终的人工内容审查和版面检查。
