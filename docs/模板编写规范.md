# 模板编写规范

## 1. 目标

本规范用于保证不同类型的交付文档具备一致的封面字段、标题层级和占位符写法，同时保留各类文档在内容重点上的差异。

## 2. 封面信息

每个模板开头均使用 YAML 元数据。默认值如下：

| 字段 | 默认值或写法 | 说明 |
| --- | --- | --- |
| `cover_title` | 对应文档名称 | 封面名称，与 H1 一致 |
| `cover_company` | `XX科技` | 默认编制单位 |
| `project_name` | `【待补充：项目名称】` | 不填写真实项目名称 |
| `document_version` | `V【待补充：版本号】` | 按实际版本替换 |
| `document_date` | `【待补充：日期】` | 使用实际发布日期 |

## 3. 标题层级

- 每个文件必须且只能有一个 H1，作为文档标题。
- H2 是一级正文标题，使用 `1. 标题` 格式。
- H3 是二级正文标题，使用 `1.1 标题` 格式。
- 不跳级；一般不超过 H5。
- H1 不作为正文目录项，封面信息由 YAML 元数据提供。

## 4. 内容边界

- 只保留通用方法、角色和字段；以 `【待补充：…】` 标注需要项目确认的信息。
- 不写入人员姓名、联系方式、账号、客户名称、真实系统地址、真实公司名称或密钥。
- 命令、配置、字段名等技术标识符使用反引号包裹。
- 表格只用于可对比字段；长篇说明写在表格外。
- 测试方案与用例的清单、覆盖和执行记录表控制在六列以内；长步骤拆为详细用例，不塞入汇总表。
- 操作手册等需要页面证据的文档，可使用 `![替代文本](相对路径 "图号 图名")` 插入本地 PNG 或 JPEG 图片。替代文本必须能够说明图片内容，双引号中的标题作为可见图注；图片与 Markdown 一起保存，不引用网络图片。

## 5. 编写提示与正文

- 每节的内容提示写成 `<!-- 编写提示：…… -->`。渲染器会忽略这类注释，避免把模板提示误当成正文。
- 正文直接写事实、条件、动作和结果，不给普通段落添加“说明：”标签。
- `应`、`须`、`不得`只用于材料明确给出的要求、安全边界或责任；步骤直接写动作。
- 少用“通常”“一般情况下”和没有适用条件的“建议”。材料不足时保留 `【待补充：具体信息】`。
- 清单使用 `- [ ] 内容`，生成的 DOCX 只显示一个紧凑方框，不再叠加项目符号。

## 6. 新增模板步骤

1. 复制一个相近的现有模板。
2. 按使用阶段放入 `templates/项目前期/`、`templates/项目过程/` 或 `templates/项目收尾/`。
3. 修改 `cover_title`、H1、H2/H3 大纲及每节编写提示，使其对应目标文档类型。
4. 保持 `cover_company: XX科技` 和通用占位符。
5. 在 `README.md` 和 `SKILL.md` 的分类目录中添加入口。
6. 更新 `scripts/validate_templates.py` 中的模板清单。
7. 执行 `python3 scripts/validate_templates.py` 并修复错误。

## 7. HITL 约束

- 模板只是大纲和写作提示，不代表已经确认的项目事实。
- 第一次输出大纲时，每节仅填写内容简述、材料来源和待补充项。
- 未收到用户对当前大纲的明确确认，不得把模板描述扩写成正文。
- 正文结构相对已确认大纲发生实质变化时，应重新请求确认。
- 详细阶段和确认格式遵循 [HITL工作流.md](HITL工作流.md)。
